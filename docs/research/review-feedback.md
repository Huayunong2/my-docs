# 复习评分反馈调研与实现方案

> 调研日期：2026-08-26  
> 范围：复习评分按钮、下一次复习预览、移动端可读性。

## 调研结论

FSRS 的官方 Rust 实现把四种评分映射为四个 next state，并返回下一次间隔；官方示例的调用顺序也是先取得 `next_states`，再读取 `again/hard/good/easy` 对应的结果。[FSRS-rs Quickstart](https://github.com/open-spaced-repetition/fsrs-rs#schedule-reviews)

因此“下次大约什么时候复习”应由服务端现有 FSRS 计算产生，前端只展示结果。不能在 TypeScript 中复制一套近似公式，否则会出现按钮预览与实际落盘日期不一致。

## 最小实现

新增只读接口：

```text
GET /api/review/:cardId/preview
```

返回四个评分的 `interval_days` 和 `next_review_at`。接口只读取当前确认卡片，不写入复习日志；评分时仍使用原有 `POST /api/review/:cardId/grade`，因此预览不会改变队列。

界面策略：

- 卡片答案展开后再请求预览，避免用户只是浏览题面就产生四次额外计算。
- 四个按钮保留颜色、中文动作和键盘 1–4 快捷键；第二行显示真实结果，例如“今天再来”“3 天后”“09-02”。
- 预览请求失败时回退为“当天重来 / 短间隔 / 正常间隔 / 长间隔”，不阻塞真实评分。
- 移动端按钮保持至少 44px 触控高度，并优先显示时间结果，不依赖颜色区分。

## 暂不做

- 不在前端复制 FSRS 算法。
- 不把预览写入 review log。
- 不在本轮增加期望保持率、每日目标等设置；这些属于学习计划配置，需要独立的持久化契约。

## 验收标准

- 预览四个间隔顺序与后端已有 FSRS 单元测试一致。
- 预览接口不增加 review_count、不改变 next_review_at。
- 评分按钮展示的预览日期与评分返回对象的 next_review_at 一致。
- 预览失败时仍可评分，且错误不覆盖复习卡片主体。
