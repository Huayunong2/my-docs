# 知识卡片批量操作调研（2026-08-26）

## 现状判断

桌面端已有选择计数、全选/反选、标签和项目批量修改、软删除与撤销；移动端虽然工具栏固定在安全区上方，但操作菜单仍沿用桌面下拉菜单，输入目标项目时会在底栏内继续展开，导致操作路径不够明确，也容易被底部导航遮挡。

## 一手资料与适用原则

- [WAI-ARIA Toolbar Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/)：当多个控件在视觉上组成一组时，可以用 `toolbar` 表达操作集合，并通过清晰标签减少用户在页面中的寻找成本。本项目已有 `role="toolbar"`，本轮保留并让移动端动作集合更易扫描。
- [Radix Dropdown Menu](https://www.radix-ui.com/primitives/docs/components/dropdown-menu)：提供焦点管理、键盘导航、typeahead 和碰撞处理，适合桌面端紧凑操作菜单；因此桌面端继续使用它，而不改成自绘菜单。
- [Anki Browsing](https://docs.ankiweb.net/browsing.html)：成熟的卡片浏览器把“选中卡片”和批量删除、切换牌组等操作分开组织，说明批量操作应围绕当前选择上下文呈现，而不是让用户逐张操作。

## 设计决策

1. 选择卡片后，移动端工具栏只保留“确认（若有草稿）”“批量操作”“清空”，目标输入移出固定栏。
2. 移动端“批量操作”打开底部 Sheet，以大触控行展示添加/移除标签、加入/移动/移出项目、移入回收站；桌面端原有下拉菜单保持不变。
3. 选择标签或项目动作后，在 Sheet 内展示输入和已有项目建议，应用按钮固定在内容末端并预留安全区；继续复用既有批量 API，不复制业务逻辑。
4. 删除仍走现有确认对话框和软删除撤销机制；移动端不增加不可恢复的快捷删除。
5. 本轮不引入新的表格/列表库；Radix Dialog/Sheet 原语已满足焦点管理、Esc 关闭和移动端分层交互。
