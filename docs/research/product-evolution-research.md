# Daily Summary 产品演进调研与改造建议

> 调研日期：2026-08-26  
> 调研范围：当前仓库的 UI、交互、数据模型、复习流程、PWA/Tauri 能力，以及成熟产品和官方组件文档。  
> 结论性质：这是产品演进建议，不是本轮代码实施清单。

## 结论先行

这个项目已经有一个清晰而有价值的核心闭环：

> 日常记录 → 从真实记录提炼知识卡片 → 按间隔复习 → 通过统计反馈学习状态。

下一阶段不建议把它扩展成 Notion、任务管理器或完整日历的复制品。更合适的方向是把这个闭环做得更稳定、更低摩擦、更适合移动端，并让数据在搜索、复习、统计和批量管理之间真正贯通。

当前 React/Vite/Tailwind/Radix/TanStack Query/React DayPicker/Tauri/PWA 的技术基础足够支撑这条路线，不需要整体迁移到 Next.js、MUI 或其他大型 UI 框架。建议采用“已有栈保留，成熟能力按需补齐”的方式：

1. 先处理移动端信息架构、路由与状态反馈、知识库工作台、批量操作撤销。
2. 再处理服务端搜索/分页、保存视图、复习目标与日记草稿恢复。
3. 最后按实际使用数据决定是否加入卡片模板、捕获箱、AI 辅助、通知和离线写入。

## 一、当前项目的基线判断

### 已具备的基础

- 前端是 React 19 + Vite + TypeScript + Tailwind 4，已有 Radix UI primitives、TanStack Query、React DayPicker、cmdk、Sonner、CodeMirror 等能力。
- 后端是 Axum + SQLite，知识卡片已有类型、状态、标签、项目关系、来源、相关卡片、使用记录和 FSRS 复习字段。
- 已经完成或具备基础的能力包括：日记录、历史/归档、统计、月历、豁免状态、知识卡片、项目、卡片复习、导入导出、PWA 和 Tauri 外壳。
- 原先提出的五项问题已有明显的基础修复：复习空状态、知识页三栏挤压、移动月历状态入口、空项目持久化、卡片批量操作。

### 当前仍然影响产品上限的结构性问题

这些不是单个按钮或样式问题，而是下一轮应优先解决的产品基础：

1. **移动导航承载过多入口。** 当前移动底栏把多项页面入口和主题切换压缩在一行，页面数量继续增加后会持续挤压文字和触控区域。
2. **页面导航状态主要存在于内存。** 当前页面、目标日期、搜索目标和知识卡片目标没有完整反映到 URL；刷新、后退、分享深链接时会丢失上下文。
3. **TanStack Query 的使用还没有覆盖主要数据流。** 目前查询缓存主要用于复习数量，其他页面仍有较多手动请求、局部 loading 和局部刷新逻辑，容易产生缓存失效或竞态。
4. **知识卡片过滤仍偏客户端。** 卡片数量增长后，搜索、筛选、排序、分页、选中状态和批量操作会互相放大成本；文章已有 FTS5，而知识卡片尚未形成同等的服务端搜索能力。
5. **复习参数偏硬编码。** FSRS 的期望保持率、新卡每日上限等策略应逐步成为可解释、可配置的学习设置，而不是只存在于服务端默认值中。
6. **PWA 缓存不等于离线编辑。** 当前 Service Worker 可以缓存应用壳，但 API 请求和写入队列、冲突处理、失败重试、幂等性还没有构成完整的离线数据模型。

## 三、UI 改造建议

### P0：移动端先解决信息架构和可操作性

#### 1. 移动底栏收敛为 4–5 个一级入口

建议底栏只保留：

- 今日
- 知识
- 复习
- 统计
- 更多

“历史、归档、搜索、设置、主题”等放进“更多”抽屉或页面。复习入口保留待复习数量 badge；“新建记录/快速捕获”可以作为页面内明显按钮或中央浮动操作，但不要再把所有功能平铺在底栏。

这样做的原因不是减少功能，而是把导航分成“高频主任务”和“低频管理任务”。用户每天真正需要反复进入的页面有限，移动端也不应该为了展示完整功能而牺牲触控尺寸和标签可读性。

#### 2. 知识页在移动端改成两级工作流

移动端不应继续压缩桌面三栏。建议：

- 第一层是卡片列表：固定搜索、筛选入口和批量选择入口。
- 点击卡片进入全屏详情/编辑页，顶部返回，底部固定保存或状态动作。
- 筛选和排序进入底部 Sheet；批量操作栏固定在底部安全区之上。
- 新建卡片使用全屏编辑页，避免在列表中再挤出一个窄表单。
- 桌面端保留列表 + 详情的 side peek，适合快速连续浏览；移动端用同一份数据和动作模型，不强行复用同一布局。

#### 3. 月历日期格只展示状态，动作集中到 Action Sheet

月历应让用户一眼看出“已记录、草稿、空白、豁免”的状态；点日期后打开操作面板，面板中提供：

- 编辑当天记录
- 选择豁免状态：休息、放假、请假、生病、出差、其他
- 清除豁免
- 查看当天统计/复习关联

日期格中不要同时放编辑、状态、更多三个小按钮。状态仍可在日期格中以文字/图标/边框表达，但不能只依赖颜色；操作面板则保证移动端一跳可达。

#### 4. 复习空状态继续保持正式，但增加“下一步”

“复习 0”不应像错误或空白页。建议形成一个稳定的状态组件：

- 标题：今日复习完成
- 数值：0 张待复习卡片
- 次级信息：下次计划时间或“当前没有到期卡片”
- 操作：查看知识库、调整今日目标、查看复习统计

同一套状态组件也应覆盖加载中、网络失败、暂无卡片、筛选无结果，避免每个页面各写一套空状态。

### P1：建立可持续的设计系统

建议增加一层语义 token，而不是继续在组件里堆颜色：

- surface：页面、面板、浮层、输入框
- text：主文本、次文本、弱文本、禁用文本
- border：普通、强调、错误
- status：记录、草稿、确认、过期、豁免、待同步、失败
- action：主要、次要、危险、幽灵
- focus：统一键盘焦点环

视觉上可以保留现有靛蓝强调色，但建议减少大面积渐变、玻璃效果和持续 pulse，把“正式感”交给层级、间距、字重、边界和状态语义。为桌面端提供舒适/紧凑两种密度，为系统减少动态效果设置 `prefers-reduced-motion` 兼容。

组件上优先补齐已经使用场景明确的 Radix primitives：Dialog/AlertDialog、Sheet 或 Drawer 组合、Checkbox、RadioGroup、Tooltip、ScrollArea、Command。可以参考 shadcn/ui 的 [Drawer](https://ui.shadcn.com/docs/components/base/drawer)、[Command](https://ui.shadcn.com/docs/components/base/command) 和 [Data Table](https://ui.shadcn.com/docs/components/base/data-table) 组合方式，但不建议为了使用 shadcn 而整体替换现有 Radix 体系。

## 四、功能优化建议

### 1. 引入真实路由和可分享的工作状态

建议逐步形成以下路由：

```text
/today
/knowledge
/knowledge/:cardId
/review
/stats
/stats/:date
/search
```

以下状态应写入 URL 查询参数：

```text
q、project、status、type、tag、sort、view、page、date、reviewMode
```

收益是刷新不丢状态、浏览器后退可用、卡片详情可分享、搜索结果可收藏，也为未来桌面深链接和通知点击打开具体页面留下入口。由于项目已经使用 TanStack Query，TanStack Router 是自然的候选；如果希望更少改动，也可以先使用轻量路由，但应坚持“页面状态可序列化”的原则。

### 2. 知识页从过滤列表升级为工作台

建议先做四个固定/可保存视图：

- 待确认：新提取或新建但尚未确认的卡片
- 本周复习：未来七天将到期或已逾期的卡片
- 未使用：创建后从未进入有效复习/使用流程的卡片
- 数据待完善：无来源、无项目、无标签或内容过短的卡片

每个视图应保存筛选、排序、分组和可见属性。详情页可把属性分成“核心信息、来源与证据、关联、复习设置、审计信息”，移动端默认只展开核心信息。

当卡片量增长后，再增加：

- 服务端分页或 cursor 分页
- 服务端排序和过滤
- FTS5 标题/正文/来源/标签搜索
- TanStack Table 的行选择和批量模型
- TanStack Virtual 的长列表虚拟化

分页和虚拟化的引入顺序应由真实数据量和性能测量决定；没有数据规模前，不要预先引入会影响编辑、键盘和选中状态的复杂虚拟列表。

### 3. 批量操作增加“范围、预览、撤销”

批量操作建议统一为以下流程：

```text
选择范围 → 显示数量 → 选择动作 → 预览影响 → 执行 → 汇总结果 → 可撤销
```

最少要明确区分：

- 选中当前页
- 选中当前筛选结果
- 全部卡片
- 清除选择
- 反选

动作建议包括确认、移动到项目、添加项目、移除项目、添加标签、移除标签、删除。删除应优先采用软删除/回收站，并在 Sonner 中提供撤销；不可逆清理再使用 AlertDialog 二次确认。

后端每次批量操作应放进事务，返回成功数、失败数和失败原因。数据量较大时返回 operation id 并显示进度，而不是让前端假设整批都成功。乐观更新只适合可以可靠回滚的场景；批量删除和移动要保留原状态快照或操作记录。

### 4. 复习从“刷卡”升级为可理解的学习计划

当前 FSRS 是正确的基础，下一步建议分两层暴露设置：

基础设置：

- 今日目标
- 每日新卡上限
- 每日最大复习量
- 新卡/到期卡顺序
- 复习提醒时间

高级设置：

- 期望保持率
- 学习日/休息日
- 项目或牌组偏好
- 逾期卡追赶策略
- 困难卡、暂停卡、Leech 处理

回答按钮上可以显示“下次大约在今天、三天后、两周后”，让用户理解选择的后果。复习首页拆分“到期、逾期、新卡、暂停/问题卡”，不要把所有数量压成一个总数。考试模式可以作为后续拓展，按目标日期生成学习量建议，但不应静默改变用户的长期复习计划。

### 5. 日记录增加清晰的生命周期和草稿保护

建议把日记录明确为：

```text
未开始 → 草稿 → 已保存
       ↘ 已豁免
```

页面顶部应显示保存状态、最后保存时间和网络状态。写作中断后要能恢复本地草稿；服务端已有更新时，要提示“保留本地/使用服务端/合并”，不能静默覆盖。

现有模板能力可继续增强为：按工作日、项目或记录类型定制模板；模板只提供起点，不要把用户锁进固定表单。可以增加可选的“下一步/跟进”字段，但要避免把产品变成完整任务管理器。

### 6. 所有页面统一查询、错误和网络反馈

建议把主要 API 迁移为统一的 TanStack Query hooks：

- query key 包含日期、筛选、分页和项目等真实依赖
- mutation 成功后只失效相关 query，不做全局粗暴刷新
- 可安全的状态切换使用乐观更新和回滚
- 网络失败显示重试、离线/暂停和待同步状态
- 批量操作使用 `toast.promise` 或等价的 pending/success/error 流程

这样能减少“列表已经更新，但详情仍是旧数据”“切换页面回来数据才刷新”等问题，也为离线阶段保留统一入口。

## 五、值得做的功能拓展

### P1：捕获箱和来源追溯

当前已经有分享入口、AI 提取和来源字段，下一步可形成“快速捕获箱”：

1. 从移动分享、桌面快捷键、粘贴 URL/Markdown、拖拽文本进入收件箱。
2. 原文先保留，用户可以稍后补项目和标签。
3. AI 只提出候选卡片、摘要和引用证据。
4. 用户通过差异视图接受、修改或拒绝。
5. 卡片保存提取来源、提示版本、模型版本和生成时间。

AI 不能无证据地覆盖用户内容；失败时要能重试或手动继续。来源和证据应成为卡片质量的一部分，而不是仅作为一个隐藏字段。

### P1/P2：卡片模板和知识关联

在基本问答卡片稳定后，再考虑：

- 基础问答卡
- 填空/删除题卡
- 多个提示对应同一知识条目
- 卡片版本历史
- 反向链接和孤立卡片视图
- 项目/来源/卡片的关系浏览

图谱可视化不是第一优先级。先提供可靠的反向链接、关联列表和“没有来源/没有关联”的质量视图；只有当用户确实需要探索关系时，再加入图谱。否则图谱很容易成为视觉演示，而不是提高复习效率的工具。

### P2：统计从“回顾”发展成“行动建议”

可以增加：

- 本周记录完成率和连续性
- 知识卡片确认率、复习完成率、逾期率
- 不同项目的复习负担
- 未来七天预计复习量
- 记录来源到卡片再到复习的转化漏斗

每个统计图都应有对应动作，例如点击逾期率进入待追赶队列、点击无来源卡片进入补全视图。避免只增加图表而不改变下一步行动。

#### 后续落地记录（2026-08-27）

统计页已增加“知识健康”区块：通过轻量的知识摘要查询展示无来源、无项目、无标签和内容过短四类问题，并将每个数量做成可点击入口，直接打开知识页对应质量视图。质量入口显式使用“全部状态”，避免已确认卡片因为知识页默认的“待确认”筛选而被漏看；同一张卡片可能命中多个问题，这一点在界面中明确说明。

这遵循“指标必须有下一步”的原则，同时复用知识页已有的服务端过滤和批量操作，不在统计页复制卡片编辑逻辑。后续只有在真实使用中证明四类问题需要更复杂的修复流程时，才增加向导或批量修复预览。

### P2：通知和离线，按阶段推进

通知可以做成可选能力：到期提醒、日记录提醒、失败同步提醒，支持静默时段和稍后提醒，默认不要打扰。

离线建议拆为三阶段：

1. **只读离线：** 缓存应用壳、最近数据和明确的离线提示。
2. **可恢复写入：** IndexedDB 保存本地草稿和 mutation outbox，写入使用幂等键。
3. **冲突处理：** 服务端 revision/ETag、冲突检测、用户选择合并结果。

Workbox Background Sync 可以作为队列实现参考，但它主要解决失败请求的重放，不会替项目决定冲突策略，也不会自动把所有 HTTP 4xx/5xx 当成可重试成功。因此离线不应作为短期宣传功能，除非上述三个边界都有验收测试。

## 六、建议的技术选择

### 保留并继续使用

- React + Vite：当前应用是本地/桌面/PWA 复用场景，迁移收益不明显。
- Tailwind：继续用于布局和 token 消费，但把重复的组件语义集中到基础组件。
- Radix：继续作为可访问交互 primitive，按需补 Dialog、AlertDialog、Checkbox、Tooltip、ScrollArea 等。
- TanStack Query：从局部使用扩展为统一数据层。
- React DayPicker：继续使用，并逐步采用 modifiers 和自定义日期组件。
- SQLite：单用户或小规模部署足够；通过事务、索引、FTS5 和外键提升质量。
- Tauri Store：适合保存主题、密度、最近项目等本地偏好，不应成为当前架构的第二个事实数据源。参考 [Tauri Store](https://v2.tauri.app/reference/javascript/store/)。

### 按需增加

- TanStack Router：解决路由、深链接和类型化搜索参数。
- TanStack Table：服务端分页后的表格/行选择/批量操作模型。
- TanStack Virtual：只在卡片列表达到实际性能阈值后引入。
- SQLite FTS5：知识卡片服务端全文搜索；中文 tokenizer 需要用真实语料验证。
- Workbox：只读缓存和后续 outbox 阶段再引入，不因“有 PWA”而直接开启离线写入。
- Playwright + Testing Library：为移动尺寸、键盘导航、批量操作和刷新恢复补充端到端/组件级验收。

### 暂不建议引入

- MUI、Ant Design、Carbon 等完整 UI 系统：会与已有 Radix/自定义 token 形成两套交互和样式规范。
- Next.js 或大规模前端迁移：当前主要瓶颈是状态和工作流，不是 SSR。
- 向量数据库/语义搜索：先把 FTS5、标签、项目和来源搜索做好；只有关键词搜索被真实场景证明不足时再做实验。
- 实时协作和多用户权限：当前产品定位和数据模型还没有这个需求的证据。

## 七、实施优先级

### 阶段 0：先定边界和验收指标

- 固化领域状态：日记录状态、知识卡片生命周期、复习队列状态、豁免状态。
- 定义移动端尺寸矩阵：390×844、768×1024、1280、1440，以及 200% 浏览器缩放。
- 补核心流程测试：创建空项目刷新、移动端日期改豁免、批量移动/撤销、复习空状态、刷新后恢复卡片深链接。
- 记录基线指标：首次记录耗时、保存失败率、卡片搜索延迟、批量成功率、撤销率、复习完成率。

### 阶段 1：优先解决当前体验痛点

1. 移动底栏收敛为主入口 + 更多。
2. 知识页移动端列表/详情分层，筛选和批量栏改为 Sheet/固定底栏。
3. 月历日期动作统一为状态展示 + Action Sheet。
4. 页面请求逐步接入 TanStack Query，补网络、加载、失败和重试状态。
5. 批量操作加入明确选择范围、事务结果、软删除和撤销。

### 阶段 2：让数据规模和复习体系可持续

1. 引入 TanStack Router 和可分享的搜索参数。
2. 知识卡片服务端过滤、分页、FTS5、排序和保存视图。
3. 增加 FSRS/每日目标/新卡与到期卡拆分等设置。
4. 增加日记录草稿恢复、版本或 revision 检查、冲突提示。
5. 增加项目/卡片/来源的数据质量视图。

### 阶段 3：验证核心闭环后的扩展

1. 捕获箱、移动分享和 AI 候选卡片差异审阅。
2. 卡片模板、填空题、版本历史和反向链接。
3. 复习量预测、考试计划和可选通知。
4. 只读离线，再评估可恢复写入和冲突处理。

## 八、明确不建议现在做的事

- 不要先做大规模框架迁移；这不会直接解决移动端挤压、状态丢失和批量操作风险。
- 不要先做炫目的知识图谱；先把关联、来源和质量筛选做成可行动的列表。
- 不要把 AI 直接接管卡片内容；候选、证据、差异和人工确认必须保留。
- 不要把颜色当成唯一状态表达，也不要把小图标或右键当成移动端唯一入口。
- 不要在没有幂等键、版本号和冲突界面前上线离线写队列。
- 不要把产品扩展成完整任务管理器；“下一步”只作为日记录和知识复习的轻量跟进。

## 九、最终推荐

如果只能选择三项下一步，我建议按这个顺序：

1. **移动端信息架构重做：** 收敛底栏、知识页两级布局、月历 Action Sheet。
2. **知识工作台升级：** URL 状态、服务端搜索/分页、保存视图、可撤销批量操作。
3. **复习和数据可靠性升级：** FSRS 设置、目标/到期拆分、草稿保护、统一 Query 缓存和错误反馈。

这三项做完，项目会从“功能已经比较齐全的个人工具”变成“每天愿意持续使用、数据增长后仍然可控的学习工作台”。AI、离线、图谱和复杂卡片模板都可以在这条核心闭环稳定后再加入。
